## 0.2.0：从零调研与机制设计

本轮用户补充：新项目可能没有任何已有 session，需要技能完成调研与沟通，再判断适合什么协作机制。已更新核心触发说明、setup 流程、UI 默认提示、README 和两份插件版本；handoff、派工及巡检规则无须变更。以下0.1.0记录与旧ZIP保留，不回写历史结果。

独立评估 agent 先读旧0.1.0，再读0.2.0。旧版已能提出合理问题，没有观察到行为失败，但指出技能缺少从零入口、调研沟通路径和分工决策条件。新版演练实际写出两轮地方口述史项目回复与机制草案：使用用户已答信息、保留未知、明确外部调研未执行、依据3人试点的依赖关系推荐先在当前对话推进，并列出首阶段任务和后续拆分条件。另对10张旅行照片任务建议单对话，未生造长期角色。主会话已逐项读回产物。

演练指出设计阶段保存简报是否等于建制有轻微歧义，已加一句明确：可以保存设计记录，但不能据此声称会话已创建或任务已承接。这项文字澄清做了静态复核，未再次运行行为演练。

原始结果：[旧版基线](outputs/greenfield/baseline.md)、[新版两轮演练与小任务](outputs/greenfield/updated.md)。每题一次、同一评估者非盲测，不证明成功率或效率改善。工具限制禁止联网和真实会话操作，因此实际调研质量、真实建聊派工及客户端加载仍未核验。

技能校验、0.2.0清单一致性、UI元数据和本机安装链接均通过。当前版打包时核对全部相对链接与ZIP逐文件一致性；旧0.1.0 ZIP保留。

## 0.1.0 历史验证记录

日期：2026-10-19。验证对象：本套件 Skill、引用模块、元数据与分发文件。

## 未加载技能的基线

独立评估 agent 在不读取新技能、旧 handoff/health-check 技能的情况下回答了 [四个场景](scenarios.md)。结果已能做到：准备具体角色方案但不擅自派工；保全 ignored 数据并实际验收后才归档；第12请求达到停止条件就停止；读取失败保留覆盖缺口，不将工作者转述当授权。

因此没有观察到可用于证明提升的基线失败。本轮不是统计 A/B 实验，也不声称本套件提高成功率或节省某个比例的成本。

## 加载后的实际演练

同一评估 agent 随后读取完整 Skill 与五个 references，写出了真实的本地演练文件；主会话读取正文核对。题设身份均为虚构测试值，未操作真实聊天和自动化。

| 检查 | 观察结果 |
| --- | --- |
| 非工程项目建制 | 生成社区展览职责索引与任务草案，复用三角色、当前聊天做总控；档期依赖与6000元总预算保留；未强加 Git 字段或重复追问建聊 |
| 不完整交接 | 仅“收到”不算接班；ignored 数据独立保全、自动化改绑核验、唯一主责切换均列为条件；指定实际承接的02做最后归档与归档后复核 |
| 预算和停止 | 第12次已达停止条件，不使用剩余8次；构建通过与效果失败分开 |
| 巡检和授权 | 保留失败cursor及覆盖缺口，无变化不催问，未把跨聊天授权转述当有效授权 |

演练发现 handoff 对调度历史差异的处理略含糊，已补成两种情况：只有过期历史且实时配置可核、无用户约束冲突时可保留配置仅改目标；涉及明确禁令、预算停止、未知任务身份或并发风险时先解决冲突。只针对这项修改做增量复核。

实际输出保存在 [演练结果](outputs/RESULTS.md)、[职责索引](outputs/docs/SESSION-MANAGEMENT.md)、[任务草案](outputs/docs/changes/EXH-001.md)、[交接演练](outputs/docs/handoffs/HO-001.md)。其中初版观察和修订后的分支验证分别记录，不能把修订后状态回写为初版已经满足。

## 静态与安装验证

- 官方 `skill-creator/scripts/quick_validate.py` 返回 `Skill is valid!`。宿主与内置 Python 均缺 PyYAML，故在独立临时虚拟环境安装验证依赖；套件无运行依赖。
- JSON 解析、两份清单名称/版本/技能路径一致、空 hooks、UI 字段长度及默认提示包含技能名均通过。
- 包内 Markdown 相对链接、引用文件存在及路径不逃逸检查；Skill 内无固定用户路径、业务仓库名或真实线程ID。
- 个人技能入口为指向完整源目录的符号链接，已读回 SKILL.md 与 handoff 模块；搬走源目录会导致该入口失效，迁移时应重装完整技能目录。

这是结构检查，不是插件平台的完整 schema/商店审核。压缩包的 ZIP CRC、17份文件清单及逐文件内容一致性检查均已通过；安装入口再次运行技能校验也通过。
