日期：2026-10-19。对象：Orchivane 0.3.1。结论：本机通过插件安装路线完成目录可见、新对话发现及实际使用验证；不是全平台认证。

## 条件与证据

- macOS本地Codex桌面；安装使用CLI 0.157.1。未单独记录桌面构建号，不将CLI版本当作桌面版本。
- 从公开GitHub来源安装 `orchivane@orchivane-local`；独立Skill已完整保留在扫描目录之外，只保留插件入口。
- 复查插件列表返回 `installed=true`、`enabled=true`、`version=0.3.1`。
- 用户在桌面插件目录看到了Orchivane，但不能确定启用状态。可见性属于用户观察；启用状态由上述工具独立核验。电脑操作工具禁止访问Codex应用，因此未由助手查看或操作UI，也未绕过限制。
- 两个测试均通过原生创建工具建立全新本地projectless对话，不是子代理或旧聊天续聊。没有在请求中提供技能路径；实际读取路径位于插件缓存，入口元数据为0.3.1。主会话读回完整回答及成功退出的读取命令。

## 新用户最小复现

1. 按[README](../README.md)添加来源并安装，核对插件列表的名称、版本及enabled状态。已有独立安装时先备份，避免重复入口。
2. 在桌面插件目录确认条目可见。目录可见不足以证明技能已被当前对话加载。
3. 新建对话输入下面的只读核验。只有读取成功并表现出对应规则，才记录实际使用通过。

```text
请只根据本轮available skills清单判断是否存在Orchivane。
有则读取声明入口及所需模块，报告名称和版本；没有则报告未发现，不搜索其他目录补救。
然后建议：一个需求尚不明确、当前只有一个对话的新项目，是否需要长期专业角色？
先澄清少量关键问题，本轮不创建、不派工、不修改文件。
```

4. 若要检查自然触发，另建标题与提示均不含插件名的对话，提出真实协作设计需求，查看是否实际读取该Skill。记录宿主、模型、其他技能与观察结果；没有读取不等于插件未安装。正式使用可明确点名，无需为了触发率重复建聊。

本包没有后台进程或自动唤醒hook；“已启用”表示可以被宿主选用，不表示每条普通请求都会执行整套协作流程。客户端未发现技能时先记录具体缺口，显式文件读取只能另计为降级成功。
