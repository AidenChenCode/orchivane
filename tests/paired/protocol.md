# Frozen paired pilot protocol
Date 2026-10-20; repo source a86ba04; Orchivane 0.3.1.
Question: under identical synthetic tasks, inputs and aggregate turn ceilings, does Orchivane reduce user coordination requests without losing quality?
One pair per task; synthetic feasibility/regression tasks, not production-representative samples. No significance or real human time claims.
Arm single: one active task chat at a time; no collaborators/subagents; may leave ordinary notes and a fresh successor for S3 only. Do not read Orchivane/session-handoff/health-check skills. Skill description remains installed: imperfect ablation.
Arm orchivane: frozen complete Skill, may choose single chat; at most one persistent specialist per task, must include it in budget. No temporary subagents in either arm. Existing host defaults retained. Record actual model/effort if exposed; mismatch excludes causal pair rather than inventing equality. Other plugins not disabled globally.
Each task/arm maximum4 aggregate model turns, including controller and all workers. Equal ceilings, NOT equal actual token/dollar spend; no enforceable token cap from native creation tool. For S1 all4 available; S2 max2 per phase; S3 max1 prepare, max2 resume, max1 duplicate. No extra repairs after outcome. Three tasks, six trials, at most24 aggregate turns and11 new chats. Common external evaluator is excluded from solver budget for both arms. No purchases, network research, archive, production writes or schedules.
Identical business brief and initial file hashes within each pair, separate directories. Role instruction and Skill availability are intentional treatment differences. Balanced randomized start order fixed below. Fresh conversation per task; S3 has an identical explicit fresh-context boundary. Post-run requests do not increase budget.
Primary proxy: extra user coordination requests (relay existing information to another role; repeat already supplied constraints; resolve role/ownership collision; reapprove already authorized step). Count distinct requested user actions, with exact evidence; do not count initial request, scheduled change, mandatory resume/duplicate, normal progress or genuine new preference questions. Also record genuine clarifications, blockers and requests needing judgment separately. Operator replies, if required: one exact reference to the already supplied brief, no hints or repairs; count as intervention. If facts truly missing, unknown and do not silently fabricate answers.
Real human coordination time: unmeasured. Researcher setup, trace collection and blind artifact grading are measurement overhead, not passed off as user savings. Agent turns, command counts and observed duration reported separately, missing cost null. A request-free incorrect/incomplete result is not a coordination win.
Quality: deterministic functional assertions plus final task state/input and side effects. Checkpoints S2 phase1 and final separately. Both identical grading scripts withheld from solvers. No skill tweaks during trial. Test grader positive/negative fixtures before run. Retain failures, skipped/missing, protocol violations and tools failures; no rerun-until-pass. If oversized or invalid, stop trial and report.
Evidence: native turns, actual commands/artifacts; no hidden reasoning published. Manual trace labels are researcher-reviewed proxies, not calibrated human study. Metadata/claim gaps remain explicit.
