## 真正暴露的问题

1. **创建与登记有时间差。** 子会话开始时索引仍标拟设；总控还曾误填占位ID，在任何后续派信前纠正。0.3.0要求只用真实创建回执、区分登记阶段，并识别登记延迟与职责冲突。
2. **版本与目录必须明确。** 0.2.0正文没有独立版本字段，项目声明提供版本；原生会话cwd不同于共享资料根。0.3.0补版本元数据和共享入口读回要求。
3. **摘要正确不代表引用可用。** 总控把原本正确的方案单独搬入design-v1快照，打断了相对引用。该失败快照故意保留；run-v2保持整个依赖目录布局，Q2验证引用和摘要一致。
4. **补丁仍可能引入矛盾。** D2补上台账异常流程，却要求停用物在复核前先转待检，与原约束冲突。Q2准确拒绝放行。0.3.0验收规则明确复查改动触及的原有约束；相关规则仅做了[限定文本复核](../../tests/outputs/v0.3/scenarios.md)，未另跑原生实验。

## 版本与公开材料

实际三角色实验读取冻结 **Skill0.2.0**，副本在 [.skill-snapshot/SKILL.md](.skill-snapshot/SKILL.md)。当前发行0.3.0是由本轮观察修订的规则，不能将本轮称为完整0.3.0重跑。安装核验属于另外三次短只读原生聊天，未执行案例：自动发现仍未出现在桌面技能清单，显式加载0.3.0可读；独立CLI0.157.1重新扫描后能发现复制安装的技能。

本目录是**脱敏导出**：绝对实验路径改为`<LAB_ROOT>`，用户原话和真实ID不公开，简报与索引是公开摘要；原生工具原始回执不包含在内。研究、方案、CSV和冻结Skill保留内容；验收记录保留实质结论。报告里的历史摘要对应原实验输入或原始报告，不自动对应经过脱敏的公开文件。公开文件摘要独立列在 [published-files.json](published-files.json)，不含清单自身。

旧快照中的断开引用是Q1问题证据，不应当作为可运行入口。阅读最终方案请用run-v2完整目录；它仍有Q2-01且未获验收通过。`AGENTS.md`及任务中描述的权限仅记录原实验，复制此案例不构成新一轮创建、发信或发布的授权。

## 覆盖边界与再现

按 [原生实验步骤](../../tests/native-e2e.md) 可在自己的隔离项目重新开展；结果不保证相同。一次非盲测不证明成功率、效率优于单会话或长期稳定性。未实测真实运营、安全分类、handoff归档、自动化首次运行、跨客户端或插件UI安装。最有价值的下一次测试是复杂需求沟通、故障恢复与安全接班，各自另设范围和停止条件。
