## 判定与留证方式

Q1 的 `review/acceptance.md` 每项记录：检查 ID、冻结输入版本、实际位置（文件与行号/CSV 库存 ID）、检查动作或推演输入、预期、实际结果、结论及问题严重度。外部事实附直接 URL 和页内段落/小节；只摘必要短句。结论用“通过／不通过／无法核验／不适用”，不适用须给理由；缺证据不能算通过。

严重度：阻断＝缺少冻结依据、越过授权或关键材料不可核；重大＝正常借还无法执行、同一物品冲突借出、逾期/损坏无处置或库存无法表达流转；一般＝局部表述、追溯或操作细节缺口。按实际影响判断，不按问题数量投票。存在阻断、重大或关键项无法核验时，不给整体通过结论。文档推演通过仅证明规则一致、可执行，不证明真实运营效果。

使用标准 CSV 读取方式解析 `design/inventory.csv`，不靠屏幕上数行；保存实际行数、唯一 ID 数与字段检查结果。接受能表达同等语义的字段或关联台账，不为验收强造字段名。

| ID | 以后如何检查 | 满足条件 |
| --- | --- | --- |
| I1 | 排除表头后计数，查空白记录、重复/空 ID；核每行代表实物还是品类、套装如何计数 | 正好 20 件可唯一识别的虚构库存；数量口径明确，不把 20 类或多件汇总误算成 20 件 |

| I3 | 核库存及其关联记录是否能表达身份、可用状态、预约时段、借还期限、异常与管理员确认 | 可定位当前占用与责任记录；初始状态合法，自由文本或关联台账也须有清楚用法；不要求填造真实借用人 |
| I4 | 对照方案逐一核所有状态值及流转，再用一件样例走完 F1、逾期与损坏分支 | 名称/语义一致；无未解释状态、重复占用或异常物品自动可借；状态模型能支持规则 |

## D. 冲突与异常桌面用例

每例从明确状态开始，记录动作顺序与管理员决定，再检查物品状态、预约/借还记录及下一步；测试数据只用虚构身份。以下是待检查场景，不是预先指定的运营政策。

| ID | 场景与检查动作 | 需要证明的结果 |
| --- | --- | --- |
| X1 | 两人对同一物品提出重叠预约；同一人重复提交；管理员先后确认 | 有去重/冲突处理依据，同一时间不出现两个有效借出承诺；无须实现在线并发系统 |
| X2 | 相邻时段预约，在交接边界、前次未归还时尝试再次确认/交付 | 是否允许相邻预约及交接条件明确；实物未回库不能直接交付给下一人 |
| X3 | 预约取消、管理员未确认或到时未领取后再次申请 | 有关闭/释放或保留的明确条件；不会遗留无法解释的占用 |
| X4 | 超过到期时间仍未归还，同时存在下一预约；借用人提出续借 | 逾期识别、管理员联系/记录与后续处理明确；若允许续借则检查冲突，若不允许则有对应处置；无擅加费用/押金 |
| X5 | 归还时发现损坏或缺配件，分别考虑原有状况已记与状况有争议 | 记录事实、暂停售借、管理员处理与重新开放条件明确；不把未经证实责任当事实，不以收费替代处置 |
| X6 | 物品遗失/长期未归还或归还记录漏填；管理员尝试直接改回可借 | 有暂停、核实、记录与纠正路径，不能凭记录缺失认定已归还；未知事项明确交管理员判断并留痕 |
| X7 | 找不到库存 ID、状态与实物不符或物品已停用时尝试预约/借出 | 暂停确认并核实，不制造第二件库存或绕过人工确认；恢复路径能解释记录如何更正 |
